# AGENT.md

Guidance for AI assistants (and humans) working in this repository. Read this
before making changes — the project has strict, automatically-enforced
conventions, and several files/directories are generated and must not be edited
by hand.

## Overview

**ent-framework** is a TypeScript library: *a PostgreSQL graph-database-alike
library with microsharding and row-level security*. Published to npm as
[`ent-framework`](https://www.npmjs.com/package/ent-framework).

It is **TypeScript-only** and **PostgreSQL-only**. Core capabilities:

- **Graph-like entities** — each domain object is an immutable `Ent` class whose
  instance maps to one row of a table.
- **Row-level security (privacy layer)** — declarative per-Ent rules decide who
  can read/insert/update/delete, expressed as graph edges between Ents.
- **Query batching & coalescing** — solves the N+1 problem transparently; you
  write per-ID code and the framework batches the underlying SQL.
- **Microsharding & replication-lag tracking** — routes queries to the right
  shard, and to a "good enough" replica or master automatically.

Tutorials live at <https://ent-framework.net>; API docs at
[`docs/globals.md`](docs/globals.md).

### `src/` subdirectories

- **`src/abstract/`** — database-agnostic layer:
  `Cluster`, `Island`, `Shard`, `Client`, `Schema`, `Query`, `Runner`,
  `Batcher`, `Loader`, `Timeline`, `QueryAnnotation`.
- **`src/ent/`** — entity framework:
  - `BaseEnt.ts` — mixin factory used as `class X extends BaseEnt(cluster, schema)`.
  - `VC.ts` — Viewer Context (the security principal of a request).
  - `Configuration.ts`, `Triggers.ts`, `Validation.ts`, `ShardAffinity.ts`,
    `Inverse.ts`, `ShardLocator.ts`.
  - `mixins/` — `ConfigMixin`, `PrimitiveMixin`, `CacheMixin`, `HelpersMixin`.
  - `rules/` — `AllowIf`, `DenyIf`, `Require` (+ `Rule`).
  - `predicates/` — reusable checks, e.g. `OutgoingEdgePointsToVC`,
    `CanReadOutgoingEdge`, `IncomingEdgeFromVCExists`.
  - `errors/` — `EntAccessError` hierarchy (`EntNotFoundError`,
    `EntNotReadableError`, `EntValidationError`, `EntUniqueKeyError`, …).
- **`src/pg/`** — PostgreSQL implementation:
  `PgClient`, `PgSchema`, `PgRunner`, and `PgQuery*` classes
  (`PgQueryLoad`, `PgQuerySelect`, `PgQueryInsert`, `PgQueryUpdate`,
  `PgQueryDelete`, `PgQueryCount`, `PgQueryExists`, …); SQL escapers in
  `helpers/` + `internal/`; custom column types in `types/`.

## Core architecture

Two orthogonal stacks meet at the `Ent` class.

**Cluster / sharding stack** (`src/abstract/`):
```
Cluster → Island (1 master + N replicas) → Shard → Client (→ PgClient)
```
The `Cluster` resolves a shard number to an `Island`; a `Shard` routes a query
to the right `Client`, choosing master vs. replica based on freshness/timeline.

**Query stack**:
```
Schema (PgSchema) → Query → Runner (PgRunner) → Batcher
```
The `Batcher` is DataLoader-like: concurrent `load()` calls are deduped by key
and flushed as a single batched SQL statement (`WHERE id IN (...)`), which is
how the N+1 problem is solved. Batchers are memoized per `Client`.

**Ent stack** (`src/ent/`): an Ent class is built by composing mixins, outer to
inner:
```
HelpersMixin( CacheMixin( PrimitiveMixin( ConfigMixin( class {} ) ) ) )
```
- `ConfigMixin` — static metadata (`CLUSTER`, `SCHEMA`, `VALIDATION`, …).
- `PrimitiveMixin` — primitive CRUD (`load`, `loadBy`, `insertIfNotExists`,
  `update`, `delete`).
- `CacheMixin` — per-VC query/result caching.
- `HelpersMixin` — ergonomic wrappers (`loadX`, `insert`, `insertReturning`, …).

**Row-level security**: every operation takes a `VC` (Viewer Context). Privacy
is declared per-Ent in `configure()` as ordered chains of **rules** evaluating
**predicates**:
- `AllowIf` — short-circuit allow (used for read rules).
- `DenyIf` — short-circuit deny.
- `Require` — must pass (used for write rules).

**Ents are immutable**: update/delete methods mutate the database and return a
boolean/Ent, but never mutate an existing instance.

## Development workflow

Requires Node (CI uses **Node 22**) and **Docker** (tests spin up PostgreSQL).
CI installs with **pnpm**; locally `npm` works against the same scripts.

```bash
npm install          # or: pnpm install
npm run dev          # tsgo --watch (incremental TypeScript build)
npm run build        # barrelsby (regen barrels) + tsc + generate docs/
npm run lint         # eslint . with cache (dist/.eslintcache)
npm run test         # starts Dockerized PostgreSQL 16, then runs jest
npm run psql         # interactive psql against the test database
npm run clean        # remove build artifacts & node_modules
```

Notes:
- `npm run test` runs `internal/with-docker-compose-up.postgres.sh` on
  `PGPORT=54832`, initializes shard schemas via `internal/init-db.sh`, then runs
  `internal/test.sh` (which does a `build` then `jest`). Docker is mandatory.
- **Run a single test**: pass a jest pattern through, e.g.
  `npm test -- Ent.generic` or `npm test -- -t "loads a row"`.
- `npm run build` regenerates `src/**/index.ts` barrels and the `docs/` folder —
  never hand-edit those; change the source and rebuild.

## Code conventions

ESLint config: `eslint.config.mjs` → `eslint.base.config.mjs`. Prettier:
`.prettierrc` (double quotes, TS parser). VS Code is set to fix-all-on-save.
Notable enforced rules:

- **One class per file**, file named exactly after the class (PascalCase, e.g.
  `PgSchema.ts`, `EntUser.ts`). Non-class utilities use lowerCamelCase files.
- **Per-method lodash imports** (`lodash/import-scope: "method"`):
  `import isEqual from "lodash/isEqual";` — **not** `import { isEqual } from "lodash"`.
- **`import type` for type-only imports** (`consistent-type-imports`).
- **Alphabetized, grouped imports** (`import/order`), newline after imports, no
  unused imports.
- **No `any`** (`no-explicit-any: "error"`); use the project's named escape
  hatches (e.g. `DesperateAny`) only when truly necessary.
- **Explicit function return types** required (except a method named
  `configure`).
- **No floating/misused promises**; prefer `async` functions; `eqeqeq`,
  `prefer-const`, `no-var`, `object-shorthand` all enforced.
- **No focused tests** in commits (`no-only-tests`).
- `internal/` directories and `__tests__/` are **excluded from the public API**
  (barrelsby ignores them) — put private implementation detail under `internal/`.

**Method-variant naming idiom** (follow it when adding APIs):
- `loadX` (throws if missing) vs `loadNullable` (returns `null`).
- `insert` (throws on unique collision) vs `insertIfNotExists` (returns
  `id | null`) vs `insertReturning` (returns the Ent).
- Update/delete return values reflect mutation; they don't mutate the instance.

## Testing conventions

- **Jest** + `ts-jest` (`jest.config.base.js`); tests match `**/*.test.ts` under
  `src/`, co-located in `__tests__/` dirs with snapshots in `__snapshots__/`.
- DB-backed tests use a shared test cluster and `PgSchema` definitions; many
  assert on captured/normalized SQL via snapshots — when behavior changes
  intentionally, update snapshots and review the diff.
- Default `testTimeout` is 30s.
- Benchmarks live in `src/pg/__benchmarks__/` (e.g. `batched-inserts.benchmark.ts`).

## Defining an Ent (canonical example)

Adapted from `examples/next-example/src/ents/EntUser.ts`:

```typescript
import { PgSchema } from "ent-framework/pg";
import { ID, BaseEnt, GLOBAL_SHARD, AllowIf, OutgoingEdgePointsToVC } from "ent-framework";
import { cluster } from "./cluster";

const schema = new PgSchema(
  "users",
  {
    id: { type: ID, autoInsert: "nextval('users_id_seq')" },
    email: { type: String },
    is_admin: { type: Boolean, autoInsert: "false" },
  },
  ["email"], // unique key
);

export class EntUser extends BaseEnt(cluster, schema) {
  static override configure() {
    return new this.Configuration({
      shardAffinity: GLOBAL_SHARD,
      privacyInferPrincipal: async (_vc, row) => row.id,
      privacyLoad: [
        new AllowIf(new OutgoingEdgePointsToVC("id")),
        new AllowIf(async (vc) => {
          const vcUser = await EntUser.loadX(vc, vc.principal);
          return !!vcUser.is_admin;
        }),
      ],
      privacyInsert: [],
    });
  }
}
```

A `Cluster` is constructed once (see `examples/next-example/src/ents/cluster.ts`)
with `islands`, `createClient`, and loggers; a request obtains a `VC` (guest,
or derived from the authenticated user) and calls `EntUser.loadX(vc, id)` etc.

## Docs & contribution notes

- **`gitbook/`** is hand-written tutorial content → edit directly.
- **`docs/`** is generated by TypeDoc (`internal/docs.sh`) → never hand-edit;
  rebuild instead. Same goes for the barrel `index.ts` files.
- `.coderabbit.yaml` enables automated PR review.
- **CI** (`.github/workflows/ci.yml`): on PRs to `main` and `grok/*/*`, and
  pushes to `main`, runs `pnpm install → pnpm run build → pnpm run lint →
  pnpm run test` on Node 22. Match these locally before pushing.
- Publishing is done via `internal/deploy.sh` (`npm run deploy`): clean →
  install → test → lint → `npm publish`.
